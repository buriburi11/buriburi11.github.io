The problem

In a link-state network, every router needs a forwarding table: for each destination, which neighbor to hand the packet to next. When a link fails, the control plane has to recompute every router's table and install the new set without readers ever seeing a mix of old and new routes. A half-updated network is how routing loops and black holes happen.

This control plane accepts topology events (INIT, LINK_DOWN, LINK_UP) and read requests (SNAPSHOT, QUERY) as line-delimited JSON over TCP, for networks of up to 64 routers.

What I built and what was provided

This was Project 3 in a computer networks course. The instructor provided the TCP server, the JSON codec, the topology graph, the Dijkstra solver with its equal-cost tie-break, the snapshot store, and the tests. I implemented the two pieces that make it a control plane:

CodeResponsibility
RoutingController.handle()Event admission rules, applying the change, computing every router's table from one snapshot, the generation number, atomic publication, and the timing audit record
ForwardingTableBuilder.build()Turning a shortest-path predecessor tree into first-hop entries for every known router, reachable or not

Architecture and tradeoffs

event ─▶ handle()   synchronized: one event at a time, in arrival order
          1. validate   reject a second INIT, and link events before INIT
          2. apply      graph.initialize(...) / graph.change(...)
          3. snapshot   one immutable GraphSnapshot
          4. for each router r:
               Dijkstra(snapshot, r) ─▶ build() ─▶ table[r]
          5. publish    new ForwardingSnapshot(++generation, tables)
                        via a single AtomicReference.set
readers ─▶ SNAPSHOT / QUERY see generation n or n+1, never a mix

Compute from one snapshot, publish with one swap

Every router's table in a generation is derived from the same immutable graph snapshot, so no generation mixes pre-failure and post-failure routes. The complete set of tables is built before anything is published, and publishing is a single reference swap. A concurrent QUERY reads whichever snapshot is current. It can see the old generation or the new one, but never a partial table. A rejected event throws before the generation changes, so the published state is untouched.

Serialized events, lock-free reads

handle() is synchronized, so route computations never overlap and a slow computation can't publish late over a newer one. The tradeoff is that events queue behind each other. Readers don't take that lock at all; they read the atomic reference. That fits a control plane, where topology changes are rare and route lookups are constant.

Building first hops from a predecessor tree

Dijkstra returns, for each reachable router, its predecessor on the shortest path. The forwarding table needs the opposite end of the path: the first hop out of the source. For each destination, build() walks predecessors back until the next step would be the source:

String hop = dest;
while (!paths.predecessors().get(hop).equals(source)) {
    hop = paths.predecessors().get(hop);
}
table.put(dest, new RouteEntry(hop, paths.distances().get(dest), true));

The loop over destinations comes from the topology's router list, not the distance map. Dijkstra leaves unreachable routers out of its results, so building only from those keys would silently drop partitioned routers. Instead they get an explicit reachable: false entry.

The end-to-end simulator drives the running engine over TCP. It checks every router's table against its own shortest-path oracle after each event, through a failure, a partition, a recovery, a repeated LINK_UP, and rejected requests:

Edge cases I had to handle

  • Partitioned routers. Covered above. Iterating the distance map would have produced tables with routers missing instead of marked unreachable. The simulator's partition step checks for exactly that.
  • Repeated link states. A LINK_UP on a link that's already up still counts as an accepted event and must advance the generation (simulator generations 5 and 6), even though no route changes.
  • Rejected events. Validation happens before any state changes, so a rejected event leaves both the published tables and the generation number exactly as they were.

What I would improve next

  • Incremental SPF. Every event reruns Dijkstra from every router, O(N · E log N). Recomputing only the trees that actually used the changed link would scale well past 64 routers.
  • Accurate acceptance time. The audit record reads acceptedNanos after the graph change has been applied. Taking it at the top of handle() would measure admission latency precisely.
